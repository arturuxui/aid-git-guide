## Архитектура

Один источник содержания → два результата.

```
content/ru/NN-<глава>.md   ← текст глав (frontmatter: id, уровень, источники «Как в AID» и дата сверки)
content/glossary.json      ← термины: RU ↔ EN ↔ как в интерфейсе GitHub ↔ сленг («запушить», «апрув»)
content/scenarios/*.json   ← сценарии симулятора: шаги + ожидаемый граф
src/core/                  ← модель git без UI: коммиты, ветки, origin, два участника,
                             merge / squash / rebase, конфликт (+ vitest)
src/diagram/               ← SVG графа коммитов из описания — одни схемы для сайта и PDF
src/ui/                    ← React + Vite (как Presentbook — дешёвый перенос при варианте «б»)
scripts/verify-commands    ← прогоняет git-команды из глав в настоящем git во временной папке
dist/                      ← статичный сайт, относительные пути (работает под /pr-N/ и в /guides/git/)
print.css → PDF            ← документ из того же источника
```

Симулятор — свой и маленький: ограниченный набор действий, говорит языком веб-интерфейса («Создать ветку»,
«Открыть PR», «Merge»), детерминирован и покрыт тестами. Learn Git Branching — внешней ссылкой, не встраиваем.

## Содержание

Каждое действие — двумя путями: где нажать в GitHub и что сказать Claude; git-команда — мелко.
В каждой главе абстрактный пример и блок «Как это в AID».

1. Зачем git: снимки, история, локальный и удалённый репозиторий, GitHub.
2. Три места: рабочая папка → stage → коммит.
3. Ветки: указатель, HEAD, `main`, имена веток.
4. Удалённый репозиторий: clone, `origin` / `upstream`, fetch, pull, push.
5. Pull Request: открыть, ревью, комментарии, draft.
6. Merge: fast-forward, merge-коммит, squash; конфликт и как его решить.
7. CI и деплой: проверки, превью, почему merge = production.
8. Командная работа: параллельные ветки, свежая ветка от `main`, форк, «`main` всегда рабочий».
9. Релизы: теги, semver, GitHub Release, Latest.
10. Issues и задачи между людьми.
11. Что-то пошло не так: отменить правку, revert, вернуть коммит, закоммиченный секрет.
12. Как просить Claude сделать это в git.
13. Продвинутое: rebase и `--onto`, cherry-pick, worktree, цепочки PR, stash, reflog.
14. Шпаргалка и глоссарий.

Интерактив: симулятор (у меня / `origin` / второй участник), сценарии-квесты («двое правят один файл → конфликт →
PR → CI → merge»), поиск по глоссарию, дерево «что делать, если…», самопроверка в конце главы.
