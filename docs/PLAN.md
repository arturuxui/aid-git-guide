# Git for Beginners — план

Гайд по git для новичков: ветки, push, PR, merge, CI и работа нескольких участников параллельно. Цель — человек,
впервые взявшийся за git, после прочтения работает с ним и говорит с командой на одном языке, а потом возвращается
к гайду за подсказками. Источник — главы `content/ru/*.md` в этом репозитории; веб-версию из них собирает Presentbook AID
(решение PD 2026-10-21).

## Формат глав

Что поддерживает сборщик Presentbook (`pages/aid-portal/scripts/external-guide-markdown.mjs`, сверено 2026-10-22):

- **Frontmatter:** `id` — адрес главы; заголовок страницы — первый `# …` в тексте (из тела он убирается).
- **HTML:** только `details`, `summary`, `small`, `br` и без атрибутов; остальное экранируется.
  Внутри `<details>` markdown не разбирается — работают только `код` и **жирный**.
- **Ссылки:** `http(s)`, `mailto`, якоря `#…` и соседние главы (`02-commit.md`); остальное становится текстом.
- **Картинки** не показываются — остаётся подпись. Иллюстрации — только схемы mermaid.
- **Mermaid** превращается в нумерованный список шагов (скриптов на странице нет). Разбираются: `flowchart` / `graph`
  с рёбрами `A["…"] -- "…" --> B`, `-->`, `-. "…" .->`; `sequenceDiagram` с `participant … as …` и `A->>B: …`;
  `gitGraph` с `commit id: "…" tag: "…"`, `branch`, `checkout`, `merge … id: "…"`. Другие формы показываются
  исходником — их не используем.
- **Без логинов и ссылок на личные репозитории** (решение PD 2026-10-21 по #275): автор — только именем.
  Пишем так, чтобы снимку не требовались правки; логины AID (`RickOBrian/aid`, `owners.json`) — можно.

Проверено 2026-10-22: все 16 файлов проходят сборщик Presentbook без исходников схем, мёртвых ссылок
и экранированных тегов. Снимок в `RickOBrian/aid` отличается от наших глав только тремя логинами — убраны в #6.

## Проверки и PDF

```
npm run check   ← scripts/check-format.mjs: главы через сборщик Presentbook из main RickOBrian/aid
npm run pdf     ← scripts/build-pdf.mjs: все главы одним PDF → dist/git-for-beginners.pdf
```

- **Формат** (CI «Формат»): исходник схемы, HTML вне белого списка, ссылка, которая станет текстом, картинка,
  логин или личный репозиторий, нет `id` или `# …`. Сборщик скачивается при каждом запуске (не копируется):
  поменяются правила Presentbook — упадёт первый же PR.
- **PDF** (CI «PDF»): тот же текст; схемы mermaid нарисованы (mermaid в Chromium через puppeteer), ответы
  «Проверь себя» раскрыты, обложка, содержание со ссылками, номера страниц. На PR — артефакт запуска
  `git-for-beginners-pdf`; на теге `v*` — файл в GitHub Release, постоянная ссылка —
  `releases/latest/download/git-for-beginners.pdf`.
- Локально Chromium ставится отдельно: `npx puppeteer browsers install chrome` (автоустановку npm блокирует).

## Содержание

Каждое действие — двумя путями: где нажать в GitHub и что сказать Claude; git-команда — мелко.
В каждой главе абстрактный пример, блок «Как это в AID» и «Проверь себя».

0. Как читать гайд.
1. Зачем git: снимки, история, локальный и удалённый репозиторий, GitHub.
2. Три места: рабочая папка → stage → коммит.
3. Ветки: указатель, HEAD, `main`, имена веток.
4. Удалённый репозиторий: clone, `origin` / `upstream`, fetch, pull, push.
5. Pull Request: открыть, ревью, комментарии, draft.
6. Merge: fast-forward, merge-коммит, squash; конфликт и как его решить.
7. CI и деплой: проверки, превью, почему merge = production.
8. Командная работа: параллельные ветки, свежая ветка от `main`, форк, «`main` всегда рабочий».
9. Релизы: теги, semver, GitHub Release, Latest.
10. Issues и задачи между людьми.
11. Что-то пошло не так: отменить правку, revert, вернуть коммит, закоммиченный секрет.
12. Как просить Claude сделать это в git.
13. Продвинутое: rebase и `--onto`, cherry-pick, worktree, цепочки PR, stash, reflog.
14. Шпаргалка и глоссарий.
