# 11. Что-то пошло не так

**Коротко.** В git почти всё обратимо: то, что попало в коммит, найти можно почти всегда.
Безвозвратно теряется только то, что **не** закоммичено, и то, что перезаписали force-push'ем
на GitHub. Поэтому главное правило: не паникуй, ничего не удаляй «на всякий случай» и сначала
спроси Claude «что случилось и как вернуть».

## Два способа отменить

| | **Revert** — «отменяющий коммит» | **Reset** — «отмотать назад» |
|---|---|---|
| Что делает | создаёт новый коммит, обратный старому | передвигает ветку назад, коммиты пропадают из неё |
| История | сохраняется: видно и ошибку, и отмену | переписывается |
| Безопасно для общих веток | **да** | **нет**: у остальных история разойдётся |
| Когда | коммит уже на GitHub, особенно в `main` | коммит только у тебя и ещё не отправлен |

Правило: **отправленное — revert, неотправленное — можно reset.**

## Рецепты

| Что случилось | Попросить Claude | Что сделает |
|---|---|---|
| Испортил файл, не коммитил | «Верни `card.css` как было в последнем коммите» | restore файла. Правки в нём пропадут насовсем — Claude переспросит |
| Опечатка в сообщении последнего коммита, не отправлен | «Исправь сообщение последнего коммита на „…“» | amend |
| Забыл файл в последнем коммите, не отправлен | «Добавь `icon.svg` в последний коммит» | amend |
| Коммиты не в той ветке (в `main`), не отправлены | «Перенеси мои коммиты из `main` в новую ветку, `main` верни как на GitHub» | новая ветка + reset `main` |
| Плохой коммит уже на GitHub | «Отмени коммит `abc123` через revert и открой PR» | revert-коммит в новой ветке |
| Слили плохой PR | в GitHub: на странице PR кнопка **Revert** | GitHub создаст PR, отменяющий этот |
| Удалил ветку после merge, а она нужна | в GitHub: на странице PR **Restore branch** | ветка вернётся |
| «Всё пропало, коммиты исчезли» | «Найди мои потерянные коммиты через reflog» | reflog помнит, где была ветка последние недели |
| Нужно переключиться, а правки не готовы | «Отложи правки» → потом «верни отложенное» | stash (глава 13) |

<small>Команды, которые встретятся в ответах Claude:</small>

```bash
git restore card.css           # вернуть файл как в последнем коммите (правки пропадут)
git commit --amend             # переделать последний коммит
git revert abc123              # отменяющий коммит
git reset --soft HEAD~1        # снять последний коммит, правки остаются в файлах
git reflog                     # где была ветка раньше
```

Видишь в предложении Claude `reset --hard`, `push --force`, `clean`, `branch -D` — это
команды, которые **стирают**. Перед «да» спроси: «что именно пропадёт и можно ли без этого?».

## Закоммитил пароль, ключ или токен

Порядок важен:

1. **Сразу смени (отзови) секрет** там, где он выдан: перевыпусти ключ, смени пароль.
   Это главное. Если коммит попал на GitHub, считай, что секрет уже утёк, — даже если
   удалишь его через минуту.
2. **Сообщи** тому, кто отвечает за этот ключ.
3. **Убери из кода** — новым коммитом. Вычищать секрет из всей истории — отдельная сложная
   работа, без договорённости с владельцем репозитория её не делают.

Не коммитил, но вывел ключ в чат с Claude или в терминал? Тоже меняй — он уже попал в журнал.

## Как это в AID

- **Свои незакоммиченные правки Claude откатывает сам.** Чужие — только спросив: «откат
  или перезапись незакоммиченной работы, которую делал не я» — в списке «Спрашиваю до действия».
- **Force-push, удаление веток и worktree — только с согласия.** Удаление данных, веток,
  ресурсов в `RickOBrian/aid` — согласие Principal Designer.
- **Merge в `main` — уже выкатка.** Плохой PR в `RickOBrian/aid` отменяют revert-PR, который
  тоже проходит CI и тоже выкатывается.
- **Секреты.** Не выводить и не коммитить; если ключ всё же вывелся — сразу написать в Штаб.
  Секреты, роли и ключи облака и GitHub — решение Principal Designer.

## Проверь себя

1. Плохой коммит уже в `main` на GitHub. Revert или reset?
   <details><summary>Ответ</summary>Revert: отправленное в общую ветку не переписывают,
   а отменяют новым коммитом.</details>
2. Ты закоммитил и запушил ключ, через минуту удалил файл и запушил снова. Всё в порядке?
   <details><summary>Ответ</summary>Нет: ключ остался в истории. Его нужно сменить
   и сообщить владельцу.</details>
3. Claude предлагает `git reset --hard`. Что спросить?
   <details><summary>Ответ</summary>Что именно пропадёт (незакоммиченные правки исчезнут
   насовсем) и можно ли обойтись без этого.</details>
